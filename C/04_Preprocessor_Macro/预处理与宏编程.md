# 预处理与宏编程

> 定位：预处理器是一个**不懂类型、不懂作用域的文本/令牌替换器**。它的每一步都在 `gcc -E` 的输出里看得见——学会看输出，比背规则有效十倍。
> 产出：写出不会咬人的宏；用条件编译做跨平台判定；用 X-macro 消灭重复表；看得懂并能修编译期符号/依赖问题。
> 状态：正文完成；示例 `xmacro_demo.c` / `macro_traps.c` / `generic_typing.c` **待实测**。

```bat
cd C\04_Preprocessor_Macro && cmd /c build.cmd
gcc -E -P macro_traps.c                          :: 只看展开结果（-P 不输出行标记）
gcc -dM -E -x c nul                              :: 打印本机全部预定义宏（nul 是 Windows 空设备）
```

## 1. 预处理发生在"翻译"之前：八个阶段（C11 5.1.1.2）

```text
1) 三字符组(trigraph ??= 等)转换 —— 基本已死，C23 移除
2) 行拼接：反斜杠 + 换行 → 删掉（所以注释里的 \ 也能续行）；源字符集 → 执行字符集
3) 切成"预处理令牌"：宏名/关键字/标识符/数字/字符串/运算符；注释替换成**一个空格**
4) 预处理：#include 展开、#define 生效、宏替换、#if/#elif/#else/#endif 求值、
          #line、_Pragma、# 与 ##、空指令删除
5) 字符/字符串字面量的转义与执行字符集编码
6) 语法分析 + 语义（类型检查、链接）
7) 所有外部符号合并（跨 TU）
8) 库初始化 → 交给 main
```

由此立刻得出四条实用结论：

```c
#define MAX 100
int arr[MAX];          /* 阶段 4 换成 100，阶段 6 才检查它是不是合法数组大小 */
int  x = MAX + 1;      /* 宏里没有类型信息：MAX 是令牌 100，不是 int 常量 */

#define ADD(a,b) a+b
int v = ADD(1,2) * 3;  /* 阶段 4 后是 1+2*3 == 7，不是 9 —— 第 6 节的主案 */

#define SWAP(a,b) { int t=a; a=b; b=t; }
/* 使用点：if (c) SWAP(x,y); else do_other();
   展开后：if (c) { ... };  else do_other();   ← 那个多余的分号让 else 找不到 if → 编译错误
   修法：把整条语句包进 do { ... } while (0)（见第 6 节铁律 2）*/
```

**指令不需要分号，且指令前后可以有空白**：`# define`、`   #endif` 都合法（`#` 后允许空格，因为 `#` 本身是"空预处理指令"）。

## 2. `#include`：它只是文本插入，但搜索规则很讲究

```c
#include <stdio.h>     /* 尖括号：只搜"系统/附加"目录（-I 指定的 + 编译器默认）*/
#include "myheader.h"  /* 引号：先搜**包含它的那个文件所在目录**，再走尖括号那套 */
```

MinGW 默认还会搜这些（本机实际列表请用命令查，**待实测**）：

```bat
gcc -print-search-dirs
gcc -print-file-name=include
echo.|gcc -v -E -xc - >nul 2> gcc_inc.log          :: 末尾的 #include <...> search starts here 就是答案
type gcc_inc.log
```

三条规则：

1. **`-I` 的顺序就是搜索顺序**，先出现者胜。想强制用自己的头：`-I` 在系统目录之前；想让某个目录里的**警告闭嘴**：用 `-isystem dir` 而不是 `-I dir`；只想作用于引号形式：`-iquote dir`。
2. **一个头文件被两次包含是否报错，取决于里面写的是什么**。typedef/声明重复 → 报错或警告；`static inline` 函数重复定义 → 每个 TU 各一份没问题；宏重定义成不同内容 → 警告。
3. 路径写法影响守卫：`#include "./a.h"` 与 `#include "a.h"` 若被 GCC 视为不同文件，**include guard 会失效**（同一个文件被真的包含两遍）。解决办法是 `#pragma once`（按文件身份而非名字判断）。

```c
/* 标准守卫：名字必须全项目唯一，惯例用 路径大写 + _H */
#ifndef C_04_XMACRO_DEMO_H
#define C_04_XMACRO_DEMO_H
...
#endif /* C_04_XMACRO_DEMO_H */
```

`#pragma once` 不是标准但 GCC/Clang/MSVC 都支持、且通常更快（少一次文件内容比对）。真实开源库还是用守卫（可移植 + 可嵌套复用）。**别混用两者来表达同一件事**，也别用 `#ifndef DEBUG` 之类的普通宏当守卫名。

**循环包含**（`a.h` 含 `b.h`，`b.h` 含 `a.h`）症状是"某类型未定义"，根因是守卫让第二次展开变成空。修法不是去掉守卫，而是：让 `b.h` 只前向声明 `struct A;` 并用指针（`03_...` 第 8 节方案 3）。

## 3. 让编译器生成头文件依赖（Make 的必需品）

```bat
gcc -MM main.c                 :: 输出：main.o: main.c util.h config.h（只列非系统头）
gcc -M  main.c                 :: 同上，但包含 /mingw64/include 里的一堆系统头（太长，一般不用）
gcc -MD -MP -c main.c -o main.o :: 编译的同时写出 main.d，并把头文件当"phony 目标"（删头文件不炸 make）
gcc -MMD -c main.c              :: = -MD 但排除系统头，最常用
gcc -MF deps.d -MT "output\main.o" -MM main.c   :: 指定输出文件与目标名
```

在 Makefile 里的标准用法（`15_Build_Library` 会完整写一份）：

```make
CFLAGS  := -std=c11 -Wall -Wextra -g -MMD -MP
OBJ     := $(addprefix output/,$(SRC:.c=.o))
-include $(OBJ:.o=.d)          # 前面的 - 表示文件还不存在时别报错
```

`-MP` 的价值：删掉某个 `.h` 后，旧 `.d` 里还引用它，没有 `-MP` 时 make 会说 "No rule to make target 'util.h'"；有 `-MP` 时它只生成一个空的 phony 规则，正常重建。**这是"改了头文件为什么不重编"类问题的正解**，不是靠 `make clean`。

## 4. 条件编译：`#if` 是一条"只有整数的表达式"

```c
#define DEBUG 1
#if DEBUG                    /* ✅ 可以写变量名：未定义的标识符在这里统统变成 0 */
#if defined(USE_TLS) && !defined(_WIN32)   /* ✅ defined() 只能用在 #if 里 */
#ifdef  USE_TLS              /* ✅ 等价 #if defined(USE_TLS)，但不能组合条件 */
#if DEBUG == 2               /* ✅ 允许 ==  <  >= && || ! 与括号，整数常量表达式 */
#endif

#if MY_FEATURE_ENABLED       /* ⚠️ 若有人 #define MY_FEATURE_ENABLED(x) ... —— 带参宏不带括号不展开，
                                   于是这里的值算作 0，条件"永远为假"且不报错 */
#endif
```

必开警告：`-Wundef`（未定义标识符参与 `#if` 时警告）与 `-Wexpansion-to-defined`（展开结果含 `defined`，标准禁止）。**注意 `-Wundef` 抓不到上面那种"带参宏漏括号"，那是另一类静默错误**——把开关写成"只定义/不定义"的形式（`#define USE_TLS`）比 `#define USE_TLS 0/1` 更不容易出错。

现代探测手段（比"猜宏名"可靠）：

```c
#if defined __has_include
#  if __has_include(<stdatomic.h>) && !defined(__STDC_NO_ATOMICS__)
#    include <stdatomic.h>
#    define HAVE_ATOMICS 1
#  endif
#endif
#if defined __has_attribute
#  if __has_attribute(format)
#    define PRINTF_LIKE(f,v) __attribute__((format(printf,f,v)))
#  else
#    define PRINTF_LIKE(f,v)
#  endif
#endif
```

`_Pragma` 与 `#pragma` 等价，唯一区别是**它能出现在宏里**（`#` 指令不能）：

```c
#define MSVC_SAFE_STRING _Pragma("warning(push,0)")    /* 只在需要时局部压掉警告 */
```

## 5. 跨平台判定：该问哪个宏（问错就是 bug）

```text
语言/实现：  __STDC__  __STDC_VERSION__（C11=201112L C23=202311L）  __cplusplus（非零=在编 C++）
              __STDC_HOSTED__  __STDC_NO_ATOMICS__  __STDC_NO_THREADS__  __STDC_IEC_559__
编译器：     __GNUC__ __GNUC_MINOR__ __GNUC_PATCHLEVEL__   __clang__   _MSC_VER   __MINGW32__
              __GNUC_STDC_INLINE__（=C99 inline 语义） vs __GNUC_GNU_INLINE__（=GNU 语义）
              ↑↑ 这一对正是 03 第 7 节 inline 坑的"开关"，跨标准移植时先测它
架构/宽度：  __x86_64__ / __i386__ / __aarch64__   _M_X64 / _M_IX86(MSVC)
              __SIZEOF_POINTER__ __SIZEOF_LONG__（LLP64 检测：指针 8 而 long 4）
              __BYTE_ORDER__ __ORDER_LITTLE_ENDIAN__
操作系统：    _WIN32（Win32/Win64 都定义！MinGW 和 MSVC 都给）  _WIN64（MinGW 也定义）
              __linux__  __APPLE__  __CYGWIN__  __ANDROID__  __MINGW64__
C 运行库：    __MSVCRT__（msvcrt）/ __UCRT__（新 UCRT）—— MinGW 上影响函数可用性
```

四条铁律：

1. **别用 `__GNUC__` 判"是不是 Linux"**。clang、MinGW、Android NDK 都定义 `__GNUC__`。判平台问 `_WIN32`/`__linux__`，判特性问 `__has_include`。
2. **判 clang 要放在判 GNUC 之前**：clang 同时定义 `__clang__` 和 `__GNUC__`（且 `__GNUC__` 伪装成 4.2）。
3. **别用宏决定 ABI**。头文件里 `#ifdef _WIN64 typedef unsigned long long ptr_t;` 这类必须与链接的库一致，改了要全项目重编（`15_Build_Library`）。
4. **MinGW 访问较新 Win32 API 要显式声明目标版本**，否则符号/结构体成员不存在：

```c
#ifndef _WIN32_WINNT
#  define _WIN32_WINNT 0x0A00      /* Windows 10；放在 <windows.h> 之前 */
#endif
```

## 6. 写宏的三条铁律

```c
/* 铁律 1：整个替换体加括号，每个参数也加括号 */
#define BAD(x)   x * 2
#define OK(x)    ((x) * 2)                    /* 外层括号保护"整体"，内层保护"参数是表达式" */
/*  1 + BAD(3+1) == 1 + 3+1*2 = 6   ❌
 *  1 + OK(3+1) == 1 + ((3+1)*2) = 9  ✅
 *  但如果参数是字符串：OK("a") -> (("a")*2) 仍然错——括号救不了语义错误，见铁律 3   */

/* 铁律 2：多语句宏必须包成一条语句 */
#define SWAP(a, b)            /* ❌ 版本 */ do { int t_=(a); (a)=(b); (b)=t_; }
#define SWAP_OK(a, b) do { int t_ = (a); (a) = (b); (b) = t_; } while (0)
/* 为什么是 do{}while(0)：
   · 它是一个"语句"，后面那个调用点写的分号正好属于它 → if (c) SWAP_OK(x,y); else ... 正常
   · 它没有作用域泄漏之外的副作用：块内的 t_ 不污染外面
   · while(0) 只跑一次；有人写 if(1){...}else 代替，那会在嵌套 else 里挂错分支 */
/* 注意：SWAP 宏要求两个同类型，且**会求值三次**——见第 9 节 */

/* 铁律 3：宏不是函数。别在宏里做需要类型知识的事 */
#define ARRAY_ELEMS(a) (sizeof(a) / sizeof((a)[0]))   /* ✅ 只能用在"数组还是数组"的地方 */
static int demo_arr[] = { 1, 2, 3 };
_Static_assert(ARRAY_ELEMS(demo_arr) == 3, "ARRAY_ELEMS must be a constant expression");
```

配套习惯：

```c
#define UNUSED(x) ((void)(x))            /* 显式丢弃，配合 -Wunused-parameter */
#define countof(a) (sizeof(a)/sizeof((a)[0]))   /* 项目里统一一个名字，别三种写法混用 */
#undef  DEBUG_FLAG                       /* 用完就取消定义，避免污染后续 TU（第 14 节）*/
```

## 7. `#`（字符串化）与 `##`（令牌拼接）

```c
#define STR(x)   #x            /* STR(1+2)   -> "1+2"（原样令牌文本，不计算！）*/
#define XSTR(x)  STR(x)        /* 两级展开：XSTR(1+2) -> STR(1+2) -> "3"? 不，仍是 "1+2" */
#define SHOW(v)  printf(#v " = %d\n", (v))     /* SHOW(a+b) -> printf("a+b" " = %d\n", a+b) */

#define CONCAT(a,b)  a##b      /* CONCAT(x,_1) -> x_1（拼成一个标识符）*/
#define CASE(v)      case v: return #v;        /* X-macro 里做名字表用 */
```

三个反直觉点，全是真坑：

1. **`#` 和 `##` 的参数不做展开**。`STR(MAX)` 得到 `"MAX"` 而不是 `"100"`。要展开必须先转一道手（上面的 `XSTR`），而 `##` 没有这么直接的等价物，标准技巧：

```c
#define CAT_(a, b) a##b
#define CAT(a, b) CAT_(a, b)   /* 多一层：a、b 先作为参数被展开，再交给 ## */
/* 用法：#define PASTE(prefix, name) CAT(prefix, name)
   PASTE(cfg_, MAX)  -> cfg_100 （若 cfg_100 不存在，得到的是这个名字，不是错误）*/
```

2. **`##` 不能拼出"合法但语义错"的东西**：`1##2` 得到令牌 `12`，`x##+` 得到 `x+`（一个令牌），后面那个常常让你踩到"看起来正常实则不同"的坑。也别指望 `##` 处理空白——它两侧的空白被忽略。
3. **拼接出的名字如果撞上保留标识符**（`_` 开头）就是 UB 范围（`02`/`03` 第 2 节）。生成符号时前缀用自己的项目名：`mylib_`、`ML_`。

生成"编号标识符"（用来在同一宏里造多个变量/多次展开同一宏）：

```c
#define UNIQUE(base) CAT(base, __LINE__)       /* 靠行号去重；嵌套展开时不可靠，慎用 */
/* GCC 提供 __COUNTER__（自增整数），比行号更适合： */
#define UNIQUE2(base) CAT(base, __COUNTER__)    /* 不是标准，但 GCC/Clang/MSVC 都有 */
```

## 8. 变参宏与日志宏的标准形状

```c
#define LOG0(...)                       /* ❌ C11/C17 要求至少一个命名参数：... 前面要有逗号前的名字 */
#define LOG1(fmt, ...)  printf(fmt "\n", __VA_ARGS__)          /* 常见但有三个问题 */
#define LOG(fmt, ...)   do { printf("[%s:%d] " fmt "\n", __FILE__, __LINE__, __VA_ARGS__); } while (0)
```

`LOG1` 的问题：① 没有 `do/while` 包裹（放进 `if/else` 会挂）；② 没有实参时 `printf(fmt "\n", )` → **尾随逗号，编译错误**；③ 无法享受编译器的格式串检查。

三种"无变参也合法"的写法：

```c
/* A) GNU 扩展：##__VA_ARGS__ 会在实参为空时吃掉前面的逗号（GCC/Clang 都支持）*/
#define LOGG(fmt, ...) do { printf("[log] " fmt "\n", ##__VA_ARGS__); } while (0)
/* B) C++20/C23 标准写法：__VA_OPT__（GCC 14+/C23 可用；-std=c11 下不可用）【待实测】*/
#define LOGS(fmt, ...) do { printf("[log] " fmt "\n" __VA_OPT__(,) __VA_ARGS__); } while (0)
/* C) 纯 C11 可移植：把变参交给一个函数处理，宏只做包装 */
void log_msg(const char *file, int line, const char *fmt, ...);
#define LOGC(...) log_msg(__FILE__, __LINE__, __VA_ARGS__)     /* ✅ 最省心，推荐 */
```

**一定要让编译器检查你的格式串**（否则 `printf("%d", 1.5)` 这类 UB 静默通过）：

```c
#if defined(__GNUC__)          /* clang 也定义 __GNUC__ 且支持同一个 attribute */
#  define PRINTF_LIKE(fmt_idx, first_arg) __attribute__((format(printf, fmt_idx, first_arg)))
#else
#  define PRINTF_LIKE(fmt_idx, first_arg)
#endif

void log_msg(const char *file, int line, const char *fmt, ...) PRINTF_LIKE(3, 4);
/*  3 = 第 3 个参数是格式串，4 = 变参从第 4 个开始。
 *  GCC 会据此报 -Wformat 的全部错误，包括实参个数/类型不符。
 *  MinGW 上若 %lld/%zu 的 -Wformat 判定不准，是 ANSI stdio 宏问题（见 gcc_g++_cmake.md），
 *  加 -D__USE_MINGW_ANSI_STDIO=1 再看。【待实测】 */
```

调试期常用开关组合（一个宏管全部，别散落 `if (verbose)`）：

```c
#ifndef BUILD_DEBUG
#  ifdef NDEBUG
#    define BUILD_DEBUG 0
#  else
#    define BUILD_DEBUG 1
#  endif
#endif
#if BUILD_DEBUG
#  define TRACE(...) LOGC(__VA_ARGS__)
#else
#  define TRACE(...) do { } while (0)      /* ✅ 空操作也要是合法语句；参数被完全丢弃 => 不会因副作用消失而改变语义 */
#endif
/* 注意最后一个陷阱：TRACE(compute()) 在 release 里**不会调用 compute()**。
   这是正确的（它本来只用于调试），但你要清楚"调试宏会删实参"这件事。 */
```

## 9. 宏 vs 函数：什么时候**不该**用宏

```c
#define SQUARE(x) ((x) * (x))
int i = 3;
int v = SQUARE(i++);      /* ❌ 展开成 ((i++) * (i++))：对 i 两次无序列点的修改 => UB（02 第 13 节）*/
int w = SQUARE(1 + 2);    /* ✅ 括号救了它 */
#define MIN(a,b) ((a) < (b) ? (a) : (b))
int m = MIN(long_fn(), 3);  /* 括号正确，但 long_fn() 可能被调用两次；
                               且 (long)与(int) 混算会走 02 第 4 节的转换规则 */
```

代价清单（宏的每一次求值都是真求值）：

| 问题 | 后果 |
|---|---|
| 参数多次求值 | 副作用/性能/UB |
| 无类型检查 | 传指针、传 `unsigned` 与 `int` 混用都照收 |
| 无法取地址 | 不能传给需要函数指针的 API |
| 调试困难 | 断点打不进宏，栈帧里没有它 |
| 名字冲突 | 宏会"吃掉"同名函数/变量（第 16 节） |

**默认答案：`static inline` 函数。** 它保留全部类型检查与调试信息，`-O2` 下与宏同样零开销（甚至更好，因为编译器能自选是否内联）：

```c
static inline int min_i(int a, int b) { return a < b ? a : b; }
static inline int square_i(int x)     { return x * x; }
```

宏只在三种场景不可替代：**需要"类型不确定"**（`sizeof` 系列、`_Generic` 分发）、**需要字符串**（`#`/`__FILE__`）、**需要生成标识符/表**（`##`、X-macro）。三者各对应本目录一份示例。

想看清宏到底展开成什么：

```bat
gcc -std=c11 -E macro_traps.c | more
gcc -std=c11 -ftrack-macro-expansion=2 -c macro_traps.c    :: 报错时显示完整展开链（GCC 扩展）
```

## 10. 编译期自检工具（写进头文件，别运行时才发现）

```c
_Static_assert(sizeof(uint32_t) == 4, "protocol needs exact 4-byte type");
_Static_assert(offsetof(struct Header, crc) == 8, "file layout frozen");
_Static_assert(_Alignof(struct Record) >= 8, "hardware DMA requires 8-byte alignment");
_Static_assert(ARRAY_ELEMS(g_table) == 16, "table must be 16 entries");
/* C23：static_assert(...) 可直接写、免分号麻烦；C11 里 _Static_assert 是万能写法 */
```

内置宏：`__FILE__`（字符串）、`__LINE__`（整数常量，会被 `#line` 改写）、`__func__`（**不是宏**，是编译器隐式提供的 `static const char[]`，函数内可用）、`__DATE__ __TIME__ __TIMESTAMP__`（**别写进发布二进制**：它们让同一份源码产生不同哈希，破坏可复现构建；要版本信息就用构建系统注入的 `-DGIT_HASH=\"...\"`）。

`assert()` 的正确姿势（`<assert.h>`，`NDEBUG` 定义后变空操作）：

```c
assert(fd >= 0 && "fd must be valid");      /* 惯用法：&& 右侧字符串恒真，只为给失败信息加描述。
                                               clang 可能对"字符串当布尔"报警告；GCC 15 待实测 */
assert(read(fd, b, n) == 0);                /* ❌ 致命：NDEBUG 后整个调用消失，逻辑被改变 */
int r = read(fd, b, n);  assert(r == 0);     /* ✅ 副作用留在 assert 之外（POSIX read；Windows 是 _read）*/
```

原则：**`assert` 只声明"调用者/程序不变式"，绝不用它做输入校验**——用户输入错误必须走错误码，`assert` 是给"这不可能发生"用的。`12_Generic_Container` 会把两者放一起对比。

## 11. X-macro：把"一张表"写一次，展开成 N 份代码

问题场景：枚举 + 字符串表 + `switch` + 解析函数，四处必须同步改，漏一处就是线上事故。X-macro（macro 里再调用 macro 参数）一次解决：

```c
/* 唯一的数据源：X(名字, 值, 显示文本) */
#define ERR_LIST(X)                       \
    X(E_OK,     0,  "ok")                 \
    X(E_IO,     1,  "i/o error")          \
    X(E_NOMEM,  2,  "out of memory")      \
    X(E_PARSE,  3,  "parse error")

/* 展开方式一：生成枚举 */
typedef enum {
#define X(name, value, text) name = value,
    ERR_LIST(X)
#undef X
    ERR_COUNT
} Err;

/* 展开方式二：生成名字表 */
static const char *const err_names[] = {
#define X(name, value, text) [name] = text,
    ERR_LIST(X)
#undef X
};

/* 展开方式三：编译期保证"表长度 == 枚举个数" */
_Static_assert(sizeof err_names / sizeof err_names[0] == ERR_COUNT, "err table out of sync");

/* 展开方式四：生成 switch */
const char *err_str(Err e)
{
    switch (e) {
#define X(name, value, text) case name: return text;
        ERR_LIST(X)
#undef X
    }
    return "unknown";
}
```

要点与限制：

- **列表项的参数形态必须固定**（这里都是三个），否则每次展开都得改宏；把 `X` 定义成三个参数并 `#undef X` 是纪律。
- 指定初始化器 `[name] = text`（C99）让枚举值与表天然对齐；若中间有跳号，表会有空洞（`NULL`），`err_str` 要判空——或者用 `switch` 版本回避。
- X-macro 里**不要放函数调用/运行时值**，它必须是编译期可展开的纯数据。
- 同一招还能生成：字段 getter/setter、序列化字段表、单元用例注册表、命令行选项表、状态机 `case` 分支。`19_Projects` 的配置解析器就用选项表版本。
- 副作用：调试器里看不到"表"，`gcc -E` 才看得到真实形状；单测覆盖每个展开分支。

## 12. `_Generic`（C11）：让编译器替你选函数

```c
#include <math.h>
#define ABS(x) _Generic((x),                    \
        int:           abs,                     \
        long:          labs,                    \
        long long:     llabs,                   \
        float:         fabsf,                   \
        double:        fabs,                    \
        default:       fabs)                    /* default 兜住未列出的类型 */

int      a = -3;
double   b = -1.5;
printf("%d %.1f\n", ABS(a), ABS(b));
```

五条必须知道的性质：

1. **控制表达式不被求值**，只取其类型 —— 所以 `ABS(i++)` 不会真的自增（与宏的"多次求值"问题正好相反，这是 `_Generic` 的最大优势）。
2. 分支里的表达式必须是**函数名或可调用表达式**；上面这种写法等价于 `abs(a)` 直接调用，`-Wall` 能正常检查参数类型。
3. **数组与函数会退化**：`_Generic(arr, int[3]: ..., int *: ...)` 永远匹配到 `int *` 那支，写 `int[3]` 分支是死代码。
4. 它**不能用来定义类型**、不能做 typedef 分发；`_Generic` 也不是编译期开关替代品（`#if` 才是）。
5. 与宏组合才好用，因为 `_Generic` 自身语法长：

```c
/* 类型安全的"入队"：一个宏，三个具体函数 */
#define BUF_PUSH(buf, val) _Generic((val),        \
        int:    ibuf_push,                        \
        double: dbuf_push,                        \
        default: _Static_assert(0, "unsupported type"))(buf, val)
/* ↑ 注意：C11 的 _Generic 里不能塞 _Static_assert，上面这行是"想法演示"。
     真实的"编译期报错"要靠把 default 指向一个不存在的函数名（链接期报错），
     或者指向一个类型不匹配的表达式（编译期报错）。见 generic_typing.c。*/
```

选型建议：**`static inline` 重载不了，`_Generic` 才上**。它适合"数值库的宽度分发"（`sqrtf/sqrt/sqrtl`）、"容器 push 分发"、"按类型打印"。别用它模拟 C++ 模板 —— 一旦 `_Generic` 嵌套三层，可读性立刻归零，那种需求请回 `12_Generic_Container` 的宏+`void*`+函数指针方案。

## 13. Windows/MinGW 的宏专项（这块 Linux 教材都不会讲）

**必须在 `#include <windows.h>` 之前定义**的开关：

```c
#define WIN32_LEAN_AND_MEAN      /* 不拉 winsock1/crypt/dde/rsa 等一大堆，编译明显变快 */
#define NOMINMAX                 /* 阻止 windows.h 定义 min/max 两个**函数宏**！ */
#include <windows.h>
```

`NOMINMAX` 为什么重要：`windef.h` 里的 `#define min(a,b) ((a)<(b)?(a):(b))` 会污染整个 TU —— 你自己的 `int min(int,int)`、或 C++ 的 `std::min(a,b)`（`<algorithm>`）都会展开成垃圾并报出十几行难以理解的错误。**看到"`std::min` 报 expected an expression"就是忘了它。**

`UNICODE`/`_UNICODE` 决定 API 名字宏的分派：

```c
#ifdef UNICODE
#  define CreateFile  CreateFileW      /* windows.h 里就是这么写的 */
#else
#  define CreateFile  CreateFileA
#endif
/* 后果：源码里写 CreateFile(...) 到底链到哪个 .lib 符号，完全由一个宏决定；
   与宽字符/窄字符混用会出现"文件名乱码"或"找不到文件"（详见 05_String_Encoding）。
   别用 TCHAR/_T()/TEXT() 写新代码：那是 Win95/NT 迁移期的产物，现在直接选 W 系 + UTF-8。*/
```

**A/W 分派的标准宏形状**（写跨 UTF-8/UTF-16 的封装时照抄）：

```c
#define ML_CAT_(a, b) a##b
#define ML_CAT(a, b)  ML_CAT_(a, b)                 /* 两层，见第 7 节 */
#ifdef UNICODE
#  define ML_SUFFIX  W
#else
#  define ML_SUFFIX  A
#endif
#define ML_API(name) ML_CAT(name, ML_SUFFIX)         /* ML_API(ml_open) -> ml_openW */
int ml_openW(const wchar_t *p);
int ml_openA(const char *p);
int (*fp)(const wchar_t *) = ML_API(ml_open);        /* 展开成 ml_openW */
```

其它常碰到的：

```text
_WIN32_WINNT / NTDDI_VERSION   目标系统版本（放在任何 windows 头之前），影响 API/结构体成员可用性
__declspec(dllexport/dllimport) 导出宏三段式（15_Build_Library 给完整可抄版本）
__inline / __forceinline         MSVC 方言；MinGW 也认 __inline。别在跨平台代码裸用
__cdecl/__stdcall/__fastcall     调用约定；WINAPI/CALLBACK 是 __stdcall 的宏（01 第 5 节）
windows.h 里的"名字地雷"        interface、small、DELETE、GET_XBUTTON_WPARAM、SendMessage/GetMessage
                                 （最后两个是宏，导致你无法取它们的函数指针）
                                 => 项目内部标识符一律带前缀，别用裸通用名词做全局符号
__STDC_WANT_LIB_EXT1__=1         Annex K 安全函数（memset_s 等）。MSVC 有，MinGW 一般没有【待实测】
                                 => 别把代码写成依赖 Annex K；用带长度参数的自写安全封装（06/12）
```

命令行传宏的引号（**Windows 上最容易踩的语法糖**）：

```bat
:: cmd.exe
gcc -DAPP_VERSION="\"1.2.3\"" main.c
:: PowerShell（引号规则不同，反引号或单引号包裹）
gcc '-DAPP_VERSION="1.2.3"' main.c
```

源码里对应 `printf("%s\n", APP_VERSION);`。忘了转义会得到 `"stringified ..."` 或直接把 `1.2.3` 当数字串报错。更稳的做法：让构建系统生成一个 `version.h`（CMake `configure_file`，见 `15_Build_Library`），别和 shell 引号搏斗。

## 14. 头文件卫生（宏视角的纪律）

```text
一个头文件 = 一份对外契约 + 一批编译期工具。里面应该有：
  ✅ include guard、feature test 宏、extern 声明、typedef、struct 前向声明、
     编译期常量（enum / #define 数字 / static inline 小工具）、导出宏
里面不应该有：
  ❌ 变量定义（第 6 节 multiple definition 之源）
  ❌ 非 static 的函数定义
  ❌ 实现用的临时宏（用完 #undef；对外宏一律项目前缀）
  ❌ 依赖"必须先包含另一个头"的隐藏要求（要么自己包含，要么改名合并）
  ❌ 影响 ABI 的宏（如切换结构体成员）散落在调用方 —— 集中到一个 config.h
```

包含顺序惯例（能自动暴露"隐藏依赖"）：

```c
#include "mymodule.h"     /* 1. 本 .c 对应的头，放最前：它若不自包含，立刻报错 */

#include <stdio.h>        /* 2. C 标准库 */
#include <string.h>

#include <third_party/lib.h>   /* 3. 第三方 */

#include <windows.h>          /* 4. 平台（很多库要求它在最前或最后，读它的文档）*/

#include "internal.h"        /* 5. 本项目其它私有头 */
```

**自包含检查**（每个头都单独编一遍，CI 里值得拥有）：

```bat
gcc -std=c11 -Wall -Wextra -Wpedantic -fsyntax-only -x c mymodule.h
:: 报"unknown type name"就是这个头缺了 #include；报"#ifndef 未闭合"就是守卫写错
```

## 15. 观察预处理器：把黑盒打开

```bat
gcc -std=c11 -E  x.c > x.i            :: 完整预处理结果（带行标记）
gcc -std=c11 -E -P x.c                :: 去掉行标记，只看代码本体
gcc -dM -E -x c nul                   :: 只列预定义宏（本机事实清单）
gcc -dM -E x.c                        :: 预定义宏 + 你 #define 的全都在
gcc -dD -E x.c                        :: 保留 #define 指令文本，同时展开（看宏定义顺序很有用）
gcc -dI -E x.c                        :: 打印每一条 #include 的展开位置（查"到底包含了哪个文件"）
gcc -H  x.c                           :: 打印包含树：... 表示嵌套深度（找"谁把这个头拉进来的"）
gcc -MM -MF deps.d x.c                :: 生成依赖
gcc -fdirectives-only -E x.c          :: 只处理 #include/#if，不展开宏（宏太乱时先看清结构）
gcc -ftrack-macro-expansion=2 -c x.c  :: 宏里的错误显示完整展开链
cpp -std=c11 -DDEBUG=1 x.c            :: 单独调预处理（cpp 存在时；MinGW 下 gcc -E 够用）
```

典型用法：
- "**为什么 `M_PI` 未定义？**" → `gcc -dM -E -x c nul | findstr STRICT_ANSI`，看 `__STRICT_ANSI__` 是否存在（`-std=c11` 会定义它）。
- "**为什么包含了 A 却拿到 B？**" → `gcc -H` 看树，`gcc -dI` 看具体行，`gcc -print-search-dirs` 看目录顺序。
- "**宏展开后代码为什么奇怪？**" → `gcc -E -P` 直接读展开结果，比猜快得多。
- "**警告文本我看不清**" → PowerShell 里 GBK 吞中文，见 `gcc_g++_cmake.md` 的 `chcp 65001` / `cmd` 重定向方案。

## 16. 陷阱清单

```c
/* 1. 宏末尾多写一个分号 —— do{}while(0) 的保护立刻失效 */
#define LOGX(m) do { puts(m); } while (0);    /* ❌ 结尾的分号必须去掉 */
if (c) LOGX("x"); else other();               /* 展开成 if(...) {...}; else → 语法错误 */

/* 2. 宏与函数同名 */
#define max(a,b) ((a)>(b)?(a):(b))
qsort(v, n, sizeof v[0], cmp);                  /* 无关 */
register_callback(max);                          /* ❌ max 被展开成 ((a)>(b)?...) —— 报错莫名其妙
                                                    补救：#undef max 再传，或 (max) 加括号抑制展开 */

/* 3. 反斜杠续行发生在"注释处理之前"——下一行被吞进注释 */
#define FLAG 1        // 说明 \
int wrong = FLAG;      /* ❌ 这行成了注释的一部分，FLAG 的定义也少了一行 */
/* 结论：宏定义里不要用 // 注释，或确保不在行尾放反斜杠 */

/* 4. #if 里写 sizeof / 类型名 —— 预处理器完全不知道这些 */
#if sizeof(int) == 4            /* ❌ sizeof 不是预处理器运算符：结果是你没想到的东西 */
#if (int) == 4                  /* ❌ 语法错或恒假 */
/* 正解：_Static_assert(sizeof(int)==4, "...");  或 gcc -dM -E 查 __SIZEOF_INT__ */

/* 5. #define 与命令行 -D 撞名且内容不同 → 警告 "redefined" */
#ifndef APP_NAME                /* ✅ 源码里给默认值前先看是否已被 -D 定义 */
#  define APP_NAME "liblearn"
#endif

/* 6. NDEBUG / _DEBUG 的位置 */
#define NDEBUG
#include <assert.h>             /* 顺序反了 → 断言仍然生效（Release 里"关不掉"就是这个原因）*/

/* 7. ## 拼出保留标识符或非法 token */
#define P(a,b) a##b
P(_, x)                          /* ❌ 生成 _x，文件作用域是保留名（UB 范围）*/

/* 8. 忘记"宏不识别作用域" */
#define T int
void f(void) { T x; }
#undef T                         /* 头文件里的宏忘 #undef → 后续 3000 行里 T 再也不是别人的 typedef */

/* 9. 字符串化宏少一层展开 */
#define S(x) #x
S(MAX)                           /* "MAX"；要 "100" 必须 S2(MAX) -> S(x) 两层（第 7 节）*/

/* 10. 把带参宏当开关用 */
#define DEBUG(x) printf x
#if DEBUG                        /* ❌ 恒假：DEBUG 是函数宏，不带括号不展开 */
#ifdef DEBUG                     /* 这条能用，但风格上应该 #define DEBUG 1/0 并写 #if */
#endif
```
