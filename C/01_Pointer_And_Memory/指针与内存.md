## 1. 一句话模型

**指针 = 一个内存地址 + 一个类型。类型不改变地址，只改变两件事：**

| 类型的作用 | 例：`int *p`（`p == 0x1000`） |
|---|---|
| 解引用时读/写多少字节 | `*p` 读写 4 字节（`char *` 读 1，`double *` 读 8） |
| 算术时的**缩放步长** | `p + 1 == 0x1004`，不是 `0x1001` |

```text
p + 1   ==   (char *)p + sizeof(*p)
p - q   ==   ((char *)p - (char *)q) / sizeof(*p)     结果类型 ptrdiff_t（有符号）
```

这条缩放规则是指针全部的"魔法"。`void *` 不能解引用也不能 `+1`，正是因为**没有类型 → 没有步长**。（GCC 把 `void *` 算术当扩展按 1 处理，标准不允许，`-Wpedantic` 会警告。）

## 2. 读声明：从里往外读

```text
规则：先找到名字，向右读（遇到 ) 或 [ 就往外配对），再往左读。
```

```c
int  *a;              /* a 是 int 的指针           */
int  *b, c;           /* ⚠️ 只有 b 是指针！c 是 int。写两行，或 typedef */
int **pp;             /* pp 指向 "int*"            */
int  arr[10];         /* arr 是 10 个 int 的数组    */
int *parr[10];        /* parr 是 10 个 int* 的数组  */
int (*ap)[10];        /* ap 是指向 "10个int数组" 的指针 —— 二维行指针 */
int (*f)(int, int);   /* f 是函数指针：签名 int(int,int) */
```

用 `typedef` 消除歧义（"星号只粘一个名字"是历史事故）：

```c
typedef int *IntPtr;
IntPtr a, b;            /* ✅ 两个都是 int* —— typedef 是类型而非文本替换 */
typedef int IntArr[10];
IntArr  m, n;           /* ✅ 两个都是含 10 个 int 的数组（不是指针！）*/
```

`typedef` 与 `#define` 的差别就在这里：`#define PI int*` 之后 `PI a, b;` 退化成 `int *a, b;`。**函数指针类型一律 typedef**，否则签名不可读。

## 3. 指针算术的合法性边界（贴着标准说）

C 只允许对**同一数组内**的指针做加减与比较，包括"末尾 + 1"这个特殊位置：

```c
int a[5];
int *p = a;      /* == &a[0]，合法 */
p + 0 .. p + 5   /* 合法：p+5 是 one-past-the-end，可比较、可存放，不可解引用 */
p + 6            /* ❌ UB：越界构造本身就是 UB，哪怕永不解引用 */
p - p            /* 合法，得 0 */
&a[0] < &a[4]    /* 合法，同一数组内比较有意义 */

int x, y;
&x < &y          /* ❌ 未指定：不同对象的相对顺序是实现定义 */
```

两个真实后果：

1. **`q - p` 只在同一数组内有意义。** 跨块相减得到的是垃圾数字，调试时"看着挺合理"反而误导。
2. `while (p < end)` 这种扫描合法，其中 `end = a + n`。**半开区间 `[begin, end)`** 能贯穿整个 C 生态的原因就在这。

```c
static char *copy_word(char *dst, const char *src, size_t len)
{
    char *d = dst;
    for (size_t i = 0; i < len; ++i) *d++ = src[i];
    return d;                    /* 返回 one-past-the-end，调用方接着往下写 */
}
```

### 3.1 数组名什么时候**不**退化

数组表达式在绝大多数上下文里转成指向首元素的指针，只有两处例外：

```c
sizeof a        /* ✅ 整个数组的字节数（编译期常量）*/
&a              /* ✅ 得到 int (*)[5]，类型里带长度 */
/* 另算半个例外：char s[] = "abc"; 是逐字节拷贝，不是把字面量地址给 s */
```

于是一批现象同时得到解释：

```c
void f(int a[5]);            /* 编译器看到的其实是 int *a；那个 5 是装饰，不做检查 */
int a[5]; f(a);              /* 传进去的是 &a[0]，长度信息彻底丢失 */
int *p = a;                  /* a 退化 -> int* */
int (*r)[5] = &a;            /* 不退化 -> 指向整个数组 */
```

`(*r)[2]` 与 `r[0][2]` 等价；`r + 1` 跳 `5 * sizeof(int)` 字节，因为**步长由指针类型决定**。这是"函数接收二维数组必须写列数"的根本原因：

```c
enum { COLS = 3 };
void row_sum(const int (*m)[COLS], size_t rows, int *out);   /* 列数进类型，行数走参数 */
```

## 4. 转换规则：只有"加 const"是免费的

```c
void *vp = p;          /* 任何对象指针 -> void*：隐式合法 */
int *ip = vp;          /* void* -> 对象指针：C 里隐式可行（C++ 必须显式转）*/
const int *ci = ip;    /* ✅ 加限定符：允许 */
int *ni = ci;          /* ❌ 去 const：-Wdiscarded-qualifiers，等于绕过承诺 */
```

`const` 沿指针链**逐层**生效：

```c
const int *p;       /* 所指不能改，指针本身可改 —— 输入参数用它 */
int *const q;       /* 指针本身不能改，所指可改 —— 少见 */
const int *const r; /* 都不能改 */
```

判据：**`const` 在 `*` 左边修饰所指，在 `*` 右边修饰指针自身。**

深层陷阱：`char **argv` 与 `const char **argv` **不兼容**，即使逐层加 const 也不行——把可写的 `char*` 装进"只能装 `const char*`"的容器后，就能借容器写入不该写的东西：

```c
void modify(const char **pp) { *pp = "literal"; }
int main(int argc, char **argv) { modify(argv); }  /* ❌ 编译器拦下 —— 这是特性不是缺陷 */
```

## 5. 函数指针与调用约定（Windows 上必须知道）

```c
typedef int (*Cmp)(const void *, const void *);
Cmp fn = strcmp_compat;              /* 函数名自动退化；&strcmp_compat 等价 */
if (fn == NULL) { /* 未设置 */ }      /* 函数指针一样能是 NULL —— 回调槽位靠它判空 */
int r = fn(&a, &b);                  /* 调用直接括号，没有 -> */
```

存进结构体就是"手工虚表"，C 唯一的面向对象手段（标准库 `FILE`、Redis `dictType` 都这么写）：

```c
typedef struct Shape {
    double (*area)(const struct Shape *);
    void   (*draw)(const struct Shape *, FILE *);
} Shape;
```

**调用约定不匹配 = 栈损坏，而且编译器不报错。**

| 约定 | 谁清栈 | 出现处 |
|---|---|---|
| `__cdecl` | 调用方 | MinGW/GCC 默认，C 运行时库 |
| `__stdcall` | 被调方 | Win32 API（`WINAPI`/`CALLBACK` 宏就是它） |
| `__fastcall` | 寄存器优先 | 少数 API |

MinGW 给 Win32 API 声明加 `__attribute__((stdcall))`，符号被修饰成 `CreateFileA@12`（`nm` 里可见）。规则：**传给 Windows 的回调必须写 `WINAPI`；纯 C 内部回调一律默认 `__cdecl`，并在 typedef 里把约定写明**，让人和编译器都能看到：

```c
typedef int (__cdecl *MyCb)(int code, void *ctx);
```

`dlsym`/`GetProcAddress` 的返回值转函数指针，严格标准下是 UB（对象指针 vs 函数指针不可互转），GCC 用 `-Wpedantic` 会警告。实用写法：

```c
union { void *obj; MyCb fn; } cast;      /* 经 union 转，绕开写法上的洁癖 */
cast.obj = dlsym(handle, "init");
if (cast.fn == NULL) { /* 加载失败 */ }
```

## 6. `offsetof`、`container_of`、柔性数组

```c
#include <stddef.h>
struct S { int a; char b; double c; };
offsetof(S, c)          /* 编译期常量：c 距结构体起始的字节偏移 */
```

**`container_of`：已知成员地址，反推宿主结构体地址。** 侵入式链表、Linux 内核 `list_head`、Redis 数据结构的基石：

```c
#define container_of(ptr, type, member) \
    ((type *) ((char *)(ptr) - offsetof(type, member)))
/*           ↑必须先转 char*：char 步长为 1，才能按字节减 */
```

原理：`&s.member` 与 `(char *)&s + offsetof(...)` 是同一地址，反向减偏移回到起点。**前提是那个指针确实嵌在结构体里**——传独立对象地址进去，得到"看起来能跑"的野指针，这是它唯一的坑，也是最致命的坑。

**柔性数组（flexible array member，C99）**：把"结构体 + 变长尾部"一次分配，省一次 malloc、省一次指针、缓存连续：

```c
typedef struct {
    size_t count;
    size_t cap;
    int    items[];        /* 不能 sizeof，不能作为唯一成员，必须最后 */
} Flex;

Flex *f = malloc(offsetof(Flex, items) + n * sizeof f->items[0]);
if (!f) return -1;
f->count = 0; f->cap = n;                    /* 注意：malloc 不清零，items 是脏内存 */
free(f);                                     /* 一次 free 全完 */
```

对比 `int *items;` + 两次 malloc：柔性数组**只有一个所有权**，不会写出"忘了释放内层"的泄漏。代价是 `sizeof(Flex)` 不含尾部、无法用 `calloc(1, sizeof(Flex))` 偷懒、且不能把 `Flex` 放进数组（元素大小不定）。`qsort` 排 `Flex**` 时得写两次间接比较（见 `13_Algorithm_SortSearch`）。

C23 起也允许 `int items[]` 与命名成员混用（`[]` 即匿名柔性），旧代码里 `int items[0]` 是 GCC 扩展，不是标准。

## 7. 动态二维数组的三种布局（选一个，别混用）

| 写法 | 内存 | 访问 | 释放 | 用在 |
|---|---|---|---|---|
| **一维展平** `T *a = malloc(r*c*sizeof*T)` | 连续 | `a[i*c + j]` | 一次 `free` | ✅ 默认选择，缓存友好 |
| 行指针数组 `T **a` | r+1 次 malloc，不连续 | `a[i][j]` | 逐行 + 顶层 | 行宽不等、按行增删 |
| 指向数组的指针 `T (*a)[c]` | 连续 | `a[i][j]` | 一次 `free` | 列数编译期已知 |

第三种常被误认为"不能动态"——列数固定、行数动态完全够用：

```c
enum { COLS = 4 };
int (*a)[COLS] = malloc(rows * sizeof *a);    /* sizeof *a == COLS * sizeof(int) */
a[2][3] = 7;
free(a);
```

`T **a` 的**分配失败清理**是它最容易被写错的地方（第 3 行失败时前 2 行已分配），标准形状：

```c
T **m = malloc(r * sizeof *m);
if (!m) return NULL;
size_t i = 0;
for (; i < r; ++i) {
    m[i] = malloc(c * sizeof **m);
    if (!m[i]) goto fail;
}
return m;
fail:
while (i > 0) free(m[--i]);                    /* 只释放成功的行 */
free(m);
return NULL;
```

`dynamic_matrix.c` 把三种布局都实现一遍并**测同序遍历耗时**——这个差异（行优先访问 vs 列优先访问）在真实项目里比大多数算法优化都值钱。

## 8. 窥探对象表示：合法的做法只有一种

```c
unsigned char *p = (unsigned char *)&x;        /* ✅ 标准明确允许用字符类型遍历任意对象 */
for (size_t i = 0; i < sizeof x; ++i) printf("%02x ", p[i]);
```

`char`/`signed char`/`unsigned char` 可以检查**任何**对象的字节表示，不算违反严格别名（这是 C 留给"底层操作"的后门）。反例是 `*(int *)&f`（`float` 当 `int` 读）——**违反严格别名，`-O2` 下可能给出错误结果**。安全替换永远是：

```c
int bits;
memcpy(&bits, &f, sizeof bits);                /* ✅ 零开销：编译器优化成一条 movd */
```

字节序实测（`05_String_Encoding` 会接着讲它对文本的影响）：

```c
uint32_t v = 0x01020304u;
unsigned char *b = (unsigned char *)&v;
/* b[0]==0x04 → 小端。x86-64 与 ARM 默认都是小端；网络字节序是大端 */
```

**结论：读写跨平台二进制文件/网络协议时不要直接 `fwrite(&struct, ...)`**——padding、字节序、`long` 宽度都会让你在某台机器上读出垃圾。用 `<stdint.h>` 固定宽度类型 + 手工序列化（大端写入：`(uint8_t)(v >> 24)` 逐字节），或用 `htobe32`/`be32toh`（Linux；MinGW 上通常要自己写，见 `18_System_Programming`）。

## 9. 内存错误分类，以及没有 ASan 时怎么抓

| 类别 | 定义 | 典型征兆 |
|---|---|---|
| 泄漏 leak | malloc/free 不平衡 | 内存单调上涨，不崩，最难发现 |
| 越界 overrun | 读写块外 | 破坏堆元数据，崩在无关的 `free`/`malloc` |
| 悬垂 dangling / UAF | `free` 后继续用 | 读到旧值、`0xfeeefeee`、随机崩溃 |
| double free | 同一块释放两次 | 立刻崩在 `free` 内部 |
| free 非堆起点 | free 栈地址/字面量/中间指针 | 立刻崩 |
| 未初始化读 | 读 `malloc` 的脏内存 | 值随运行变化，"有时是对的" |

`-fsanitize=address` 在你这套 MinGW 上是否可用仍标 **待实测**。不可用时三板斧：

1. **调试期把 `malloc` 换成 `calloc`**：清零让"未初始化读"从随机变成稳定可复现。
2. **`free` 后置 `NULL` + 自写 debug allocator**：记录 `__FILE__`/`__LINE__`，退出时列出未释放块。完整实现放 `14_Memory_Management`，模式先记住：

   ```c
   #define XMALLOC(n) xmalloc_dbg((n), __FILE__, __LINE__)
   void *xmalloc_dbg(size_t n, const char *file, int line);
   ```

3. **gdb 硬件观察点**——怀疑某块被越界写时，让它自己供出凶手：

   ```text
   (gdb) break main
   (gdb) run
   (gdb) p buf                     ← 拿到可疑地址
   (gdb) watch *(int*)0x1234abcd   ← 该地址被写入时立刻中断（调试寄存器，槽位有限，4/8 字节最稳）
   (gdb) bt                        ← 栈回溯直接指出越界那一行
   ```

   **"没有 ASan 就抓不到越界"是误解：一个 `watch` 常常胜过读一小时代码。** 更多手段见 `16_Debug_Tools/`。

## 10. 栈、递归深度、`alloca`

自动存储期对象活在栈上。Windows 为每个线程保留栈空间，**默认大小由链接器决定**，MinGW 生成的 exe 常见为 1 MB（`msvcrt`/exe 头里写着，可能与你的构建不同——**待实测**）：

```bat
objdump -p output\rec.exe | findstr /i "SizeOfStackReserve SizeOfStackCommit"
```

想改：

```bat
gcc -std=c11 -Wa,--subsystem,console -Wl,--stack,16777216 rec.c -o output\rec.exe
::                                   ↑ 16 MB：只在你真的需要深递归时用，别当默认
```

递归爆栈的表现是**立刻崩（`EXCEPTION_STACK_OVERFLOW`）而不是慢慢变慢**，而且 gdb 里栈帧常常已经不可信。三件事：

- 递归必须有**必然到达**的基准情形（`while` 能改写成递归不代表该改）。
- 深度上限要显式传参保护：`parse(node, depth)`，`if (depth > MAX_DEPTH) return -ELOOP;`——解析嵌套 JSON/表达式时这是防 DoS 的第一道墙（`19_Projects` 里会踩到）。
- 别用 VLA 和巨型局部数组（`int buf[1<<20];` 直接吃掉 4 MB）；大缓冲一律走堆。

`alloca` 在栈上按运行时长度分配，**释放自动但溢出无检测**，GCC 支持、MSVC 支持、标准从未收编（C23 也没有）。规则：**不要用**，需要变长就用 `malloc`，需要零开销就用固定上限 + 截断报错。

## 11. 陷阱清单（每条都对应一次真实事故）

```c
scanf("%d", n);                    /* 1. 忘了 & —— n 被当地址写 → 崩 */
char *f(void){ char b[10]; return b; }  /* 2. 返回局部地址 → 悬垂 */
malloc(n * sizeof p);              /* 3. sizeof 用错对象 → 只分配了 n*8 的一半 */
size_t n = sizeof a / sizeof *a;   /* 4. 在函数里对指针参数求长度 → 恒为 2，毫无意义 */
q = malloc(...); q++; free(q);     /* 5. free 不是原始起点 → UB */
p = realloc(p, n);                 /* 6. 失败时原指针被 NULL 覆盖 → 泄漏，且 p 已不可用 */
if (strcmp(a, b)) { }              /* 7. 三态当二态：漏了 == 0，逻辑整个反掉 */
int addr = (int)(void *)p;         /* 8. LLP64 下 int 32 位 → 截断。只有 intptr_t 能存指针 */
*p++;                              /* 9. 等价 *(p++)：++ 优先级高于解引用 */
short *s = (short *)(buf + 1);     /* 10. 未对齐访问：x86 能跑但慢，ARMv7 直接崩 → 用 memcpy */
```

第 8 条在 Windows 上格外真实：**LLP64 下 `long` 也是 32 位**，用 `long` 存句柄/指针同样截断。存指针整数只用 `intptr_t`/`uintptr_t`；存 Win32 句柄用 `HANDLE`/`UINT_PTR`。

第 10 条的标准解法永远是 `memcpy`，现代 GCC 会把它优化成一条 load/store，**零开销**：

```c
uint32_t v;
memcpy(&v, buf + off, sizeof v);      /* ✅ 不要求对齐，也不违反严格别名 */
```
