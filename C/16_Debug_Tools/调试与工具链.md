# 调试与工具链

> Stage 4 ｜ `C/16_Debug_Tools/` ｜ 计划：**第 5 批**（骨架）

## 一句话定位
`printf` 只能验证"我猜对了"，调试器能回答"到底哪里错了"。C 的 bug 常在崩溃点之后才暴露，必须能看内存和栈。

## 待覆盖
- gdb：`break/next/step/finish`、`print/x`、`x/16gx`、`info locals/registers/frame`、条件断点、watchpoint
- VS Code + gdb 的 `launch.json`（MinGW 路径、`miDebuggerPath`）
- 崩溃现场：`bt` 读栈帧、`core`/异常码、`main` 前崩溃
- `objdump -d -M intel` / `nm` / `size` 读符号与段
- 优化后调试的陷阱：变量被消、内联改行号、`-Og`
- 静态检查：`-Wall -Wextra -Werror` 全开 + 未装的 `cppcheck` 替代方案
