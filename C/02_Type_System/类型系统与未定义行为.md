# 类型系统与未定义行为

> Stage 1 ｜ `C/02_Type_System/` ｜ 计划：**第 2 批**（骨架）

## 一句话定位
C 的类型系统不是"防错机制"，而是**给编译器生成指令的许可证**。理解整型提升与严格别名，才能解释为什么 `unsigned` 减法会绕回、为什么把 `int*` 硬转成 `float*` 在 `-O2` 下会崩。

## 待覆盖
- 整型提升 / Usual Arithmetic Conversions（含 `char + char`、`int + unsigned`、`size_t` 与有符号混算）
- 赋值转换与 `%zd`/`%zu` 的正确用法
- 严格别名规则 + `typeof`/`memcpy`/union 三种破法
- UB 清单：有符号溢出、空指针解引用、越界、返回局部变量地址、未初始化读
- UB vs 实现定义 vs 未指定行为
- `_Bool` 转换、`_Complex`、`long long`、C23 `_BitInt` / `bool` 关键字差异
