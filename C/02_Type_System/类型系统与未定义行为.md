## 1. 三种"标准没给你答案"的情况（术语必须分清）

| 术语 | 含义 | 你的责任 |
|---|---|---|
| **未定义行为 UB** | 标准完全不保证，**包括"看起来正常"**。编译器可以假设这段代码永不到达 | 绝不能依赖任何观察结果，包括"我跑了 100 次都对" |
| **未指定行为** | 有若干可接受结果，选哪个由编译器决定（如函数实参求值顺序、`&x < &y` 对不同对象） | 结果合法但别指望跨编译器一致 |
| **实现定义行为** | 编译器必须在文档里选一个（如 `char` 有无符号、`wchar_t` 宽度、右移负数） | 查文档，或写代码把它测出来（本目录示例就干这个） |

关键认知：**UB ≠ 崩溃**。UB 是"程序进入编译器不愿负责的状态"。崩溃只是它最仁慈的表现。更常见的表现是：

- 结果看起来对，但换 `-O2` 就错；
- 换个 GCC 小版本就错；
- 加一行无关代码就错（因为优化决策变了）；
- 安全检查被当成"死代码"删掉（第 8 节给实例）。

## 2. 整型全景（本机 MinGW x86-64 / LLP64）

| 类型 | 字节 | 范围 | 字面量 | `printf` |
|---|---|---|---|---|
| `char` | 1 | 实现定义：GCC/x86 为 -128..127 | `'A'` | `%d`（会提升） |
| `signed char` / `unsigned char` | 1 | -128..127 / 0..255 | — | `%d` / `%u` |
| `short` / `unsigned short` | 2 | -32768..32767 | `42` | `%d` / `%u` |
| `int` / `unsigned` | 4 | ±2147483648 / 0..4294967295 | `42` / `42u` | `%d` / `%u` |
| `long` / `unsigned long` | **4** | 同 `int` | `42L` / `42UL` | `%ld` / `%lu` |
| `long long` / `unsigned long long` | 8 | ±9.2e18 | `42LL` / `42ULL` | `%lld` / `%llu` |
| `size_t` | 8 | 0..2^64-1 | — | `%zu` |
| `ptrdiff_t` | 8 | 有符号 | — | `%td` |
| `intptr_t` / `uintptr_t` | 8 | 能安全往返指针 | — | `%td` / `%tu`（与 `ptrdiff_t`/`size_t` 同宽时） |
| `intmax_t` / `uintmax_t` | 8 | 最大宽 | `42` + 转 | `%jd` / `%ju` |
| `int8_t`..`int64_t`（`<stdint.h>`） | 精确位宽 | 固定 | — | 见下方提示 |

三条最容易记错的：

1. **Windows 64 位是 LLP64：`long` 只有 4 字节。** Linux/macOS 是 LP64，`long` 是 8。`%ld` 打印 64 位值在两边行为不同 —— 跨平台代码用 `int64_t` + `PRId64`，别用 `long`。
2. **标准只保证下限**：`int` ≥ 16 位、`long` ≥ 32 位、`long long` ≥ 64 位、`sizeof(char)==1` 恒成立、`char ≤ short ≤ int ≤ long ≤ long long`。所以"我以为 int 是 4 字节"必须由示例打印确认，不是常识。
3. `int8_t` **提升成 `int`**，所以打印小整型直接用 `%d`/`%u` 即可（除非要 `%hhd` 演示截断）；`<inttypes.h>` 的 `PRId32` 之类的用途是给**固定宽度类型**写可移植格式串：`printf("%" PRId64 "\n", v);`

**选类型规则（照做，不用思考）**：

```text
计数/长度/字节数/下标  -> size_t          指针差 -> ptrdiff_t
需要精确位宽（协议、文件格式、哈希）-> uint32_t / int64_t 等 + <stdint.h>
循环变量/普通整数        -> int            标志位 -> int 或 bool
文件偏移                -> long long + %lld，或平台类型 ftello 系列
存指针的整数            -> intptr_t        需要最大范围 -> intmax_t
```

## 3. 整型提升：窄类型进运算就**不再是窄类型**

```text
整数提升（integer promotion）：
  char / signed char / unsigned char / short / unsigned short / _Bool / enum
      → int         （若 int 装不下该类型的所有值，则 → unsigned int）
```

于是：

```c
char x = 30, y = 30;
printf("%d\n", x + y);          /* 60 —— 不是 char，也不做 char 溢出检查 */
printf("%zu\n", sizeof(x + y)); /* 4  —— 结果类型是 int，不是 1！ */

unsigned char a = 200, b = 200;
printf("%d\n", a * b);          /* 40000 —— int 装得下，所以没有溢出 */
short s = 40000;                /* ⚠️ 40000 超 short 范围？不：short 上限 32767 → 实现定义的转换 */
```

**为什么 C 要这么设计**：表达式在 CPU 里就是在机器寄存器（≥32 位）上算的，让窄类型先"名正言顺"地进入 `int`，避免每个运算都插入截断指令。副作用是：**你以为在 char 上的运算，其实发生在 int 上**，`200 + 200` 不会绕回。这条推论直接解释了 `isdigit()` 那类函数的正确调用方式（第 9 节）。

**赋值回窄类型时才截断**：

```c
char c = 200 + 200;      /* 400 截断到 char：400 & 0xFF = 144 → 有符号 char 下是实现定义值 */
```

## 4. 通常算术转换：`int` 与 `unsigned` 相遇时谁赢

完整算法（`a op b`，先做上面的整数提升，再反复应用"两边不同则取公共类型"）：

```text
1) 任一侧是浮点：long double > double > float，按浮点统一
2) 同一符号性        ：取更宽的类型
3) 一侧无符号 U，一侧有符号 S：
     若 rank(U) >= rank(S)          -> 结果 U          ⚠️ unsigned int 赢过 long！
     若 S 能表示 U 的全部值          -> 结果 S
     否则                           -> 结果 U 对应的无符号类型
```

`rank`（等级）顺序：`long long > long > int > short > char`。

真实事故（第 3 条前两个分支）：

```c
int      i = -1;
unsigned u = 1;
printf("%d\n", i < u);            /* 0！ i 被转成 4294967295 —— 比较完全反过来 */

size_t n = 0;
printf("%zu\n", n - 1);           /* 18446744073709551615 —— 无符号减法绕回，不报错 */
for (size_t k = n - 1; k >= 0; --k) { }   /* 死循环：size_t 永远 >= 0 */

/* 32 位 MinGW 上：long(4B) 与 unsigned(4B) 同宽 → rank 相同 → 结果 unsigned，long 输 */
long lg = -1; unsigned un = 1;
printf("%d\n", lg < un);          /* 0 —— 违反直觉，且和 64 位 Linux 上结果不同！ */
```

**工程规则三条**：

1. **循环变量与容器长度同类型**，或者永远转成有符号前先判空：
   ```c
   for (size_t k = 0; k < n; ++k) { }            /* ✅ 只用递增 */
   for (size_t k = n; k-- > 0; ) { }             /* ✅ 倒序的标准写法（先判后减，n==0 安全）*/
   if (n > 0 && (size_t)(n - 1) < cap) { }        /* ✅ 想减就先确认非 0 */
   ```
2. 混算前先**显式转换**，让意图出现在代码里：`(long long)a * b`、`(unsigned)i`。
3. 打开 `-Wsign-compare`（在 `-Wextra` 里）与 `-Wconversion -Wsign-conversion`（不在，自己开，见第 13 节）。

## 5. 溢出：有符号是 UB，无符号是定义行为

```c
int  a = INT_MAX;  a + 1;              /* ❌ UB。不是"变负数"，是"编译器可假设永不上溢" */
unsigned b = UINT_MAX; b + 1;          /* ✅ 定义：模 2^32 回绕成 0 */
int c = INT_MIN; -c;                   /* ❌ UB：-INT_MIN 装不下 */
int d = INT_MIN / -1;                  /* ❌ UB（x86 上会抛 #DE，实机 SIGFPE/崩溃）*/
abs(INT_MIN);                          /* ❌ 同样 UB：结果无法用 int 表示 */
```

安全写法：

```c
int safe_abs(int x) { return x == INT_MIN ? INT_MAX : (x < 0 ? -x : x); }   /* 或返回 long long */
long long acc = (long long)a * b;       /* 先升级到能装下的宽度再乘 —— 别用 int 平方 */
if (n > SIZE_MAX / sizeof *p) { return -1; }   /* 分配前的乘法溢出检查 */
p = calloc(n, sizeof *p);               /* ✅ calloc 自带乘法溢出检测，返回 NULL 而不是分配小块 */
```

调试期武器：

```bat
gcc -std=c11 -fwrapv x.c          :: 让有符号溢出按补码回绕（GCC 扩展）——只用于"暂时让它可预测"，别当设计
gcc -std=c11 -fsanitize=undefined -fno-sanitize-recover=all x.c   :: UBSan，报 signed-integer-overflow 等。MinGW 可用性【待实测】
```

**为什么编译器敢删掉溢出检查**：`if (x + 1 < x) overflow_detected = 1;` 里，标准规定有符号溢出是 UB，于是编译器有权假设 `x + 1 > x` 恒成立，**把整个 if 当死代码删掉**。这是第 12 节"UB 不崩但改结果"的最典型样本。

`int f(int i) { return i + 1; }` 在常量上下文里（`enum { N = INT_MAX + 1 };`）GCC 会**直接报错**（`-Woverflow`）：编译期 UB 有诊断，运行期 UB 没有。**别把"编译器没警告"当"没有 UB"。**

## 6. 除法与取模

```c
x / 0        x % 0         /* ❌ UB（整数）。崩溃在 x86 上是 #DE 异常 → SIGFPE */
INT_MIN / -1               /* ❌ UB（见第 5 节）*/
-7 / 2    == -3            /* ✅ C99 起向零截断（C90 是实现定义，老教材会告诉你 -4，那是老规则）*/
-7 % 2    == -1            /* ✅ 余数符号跟被除数；(a/b)*b + a%b == a 恒成立 */
7 % -2    == 1             /* 除数符号不影响 */
```

推论：`a % b == 0` 判断整除时，**负数会让余数为 -0（等于 0）** 所以没问题；但 `a % b == 1` 在 `a < 0` 时永远不成立（得到 -1）。哈希、环形缓冲索引必须先规范化：

```c
static size_t wrap_mod(long long i, size_t n)     /* 把任意整数安全折进 [0,n) */
{
    long long r = (long long)(i % (long long) n);
    return (size_t) (r < 0 ? r + (long long) n : r);
}
```

浮点除零：C 标准同样把它列为 UB；IEEE-754 实现（GCC 默认）给出 ±Inf 而不异常。所以 `1.0 / 0.0` 在 MinGW 上得到 `inf`，**但别写进代码**——用 `isinf` 判定或先检查除数。

## 7. 浮点：不是"近似的小数"，是"二进制的有理数之和"

```text
double = 1 位符号 + 11 位指数 + 52 位有效位（隐含 1 位）→ 约 15~17 位十进制有效数字
float  = 1 + 8 + 23  → 约 6~9 位；整数值只在 |x| <= 2^24 (=16777216) 内精确
```

`0.1` 写不成二进制有限小数，所以：

```c
printf("%.17g\n", 0.1);      /* 0.10000000000000001 —— 它从来不是 0.1 */
printf("%a\n", 0.1);         /* 0x1.999999999999ap-4 —— 十六进制浮点是"照妖镜"，C99 起标准支持 */
if (0.1 + 0.2 == 0.3)        /* ❌ 永远不成立：左边是 0.30000000000000004 */
```

**不要用 `DBL_EPSILON` 当万能容差**，它是 1.0 附近的间距，不是"最小正数"（那是 `DBL_MIN`/`DBL_TRUE_MIN`）：

```c
#include <float.h>
#include <math.h>
static int near_eq(double a, double b)          /* 相对容差 + 绝对容差兜住 0 附近 */
{
    double d = fabs(a - b);
    double m = fmax(fabs(a), fabs(b));
    return d <= 1e-9 || d <= 1e-9 * m;          /* 阈值按业务量级定，别抄 1e-9 就完事 */
}
```

必须知道的几条行为：

```c
NaN  : 任何含 NaN 的比较都为假；x != x 为真当且仅当 x 是 NaN；用 isnan()/isfinite() 判
Inf  : 溢出到 ±Inf（IEEE 实现下不崩）；isinf() 判
累加 : 从小到大加误差更小；大量求和用 Kahan 补偿或 long double 累加（13_Algorithm_SortSearch 会实测）
顺序 : (a+b)+c != a+(b+c) —— 浮点加法不满足结合律，这是数学事实不是 bug
精度 : double 运算赋值给 float 会截断；函数实参 float 会提升为 double（第 3 节的浮点版本）
      GCC 有 -Wdouble-promotion，专门抓"我以为在用 float"
```

`-ffast-math` **不要在生产代码里随手加**：它允许重结合、假设无 NaN/Inf、放松精度，几何鲁棒性/金融/校验和代码会被静默改变语义。想快就用 `-O2` + 明确向量化选项，需要 `-ffast-math` 时把这段计算隔离成一个独立编译单元并写明理由。

x86 相关：32 位 x87 下 `DBL_EVAL_METHOD == 2`（中间量按 `long double` 算），会出现"存进 double 再读出来结果不同"的比较反转；x86-64 默认 SSE，`DBL_EVAL_METHOD == 0`。打印它确认本机情况（示例里做了）。

**`M_PI` 的 MinGW 陷阱**：`-std=c11` 会定义 `__STRICT_ANSI__`，某些 mingw-w64 头因此**不提供 `M_PI`**，编译报"undeclared"。稳妥做法：自己 `enum`/`static const double` 定义，或加 `-D_USE_MATH_DEFINES`，或用 `-std=gnu11`。**【待实测】**——本目录示例不依赖 `M_PI`。

字符串与浮点互转：`strtod`（能报告结束位置与错误）、`snprintf(buf, size, "%.17g", v)` 保证可 round-trip；`%f` 默认 6 位小数**不保证能还原原值**。

## 8. 字符类型家族：把"字节"和"字符"分开

| 类型 | 本机宽度 | 语义 | 用途 |
|---|---|---|---|
| `char` | 1 | 实现定义有无符号（GCC/x86 = signed） | 平台默认窄字节；字符串 |
| `signed char` | 1 | 一定 signed | 需要 -128..127 的数值 |
| `unsigned char` | 1 | 一定 unsigned，0..255 | **二进制缓冲、字节序窥探、表索引** |
| `wchar_t` | **2**（MinGW） | 宽字符，Windows 上等价 UTF-16 code unit | `L"..."`、`fwide`、Win32 W 系 API |
| `char16_t` | 2 | UTF-16 code unit（C11） | `u"..."` |
| `char32_t` | 4 | UTF-32 code point（C11） | `U"..."` |
| `char8_t` | — | 不是 C11/C17 标准类型（草案曾加又撤） | 别用；要 UTF-8 就用 `char`/`unsigned char` |

两条必背：

```c
/* 1) char 有无符号是实现定义 —— 所以"存字节"永远写 unsigned char */
char c = buf[i];              /* 若 char 是 signed，0xFF 变成 -1 */
int  v = c;                   /* 符号扩展成 -1，不是 255 —— 哈希/校验和的经典错误 */
int  v2 = (unsigned char) c;  /* ✅ 0..255 */

/* 2) <ctype.h> 与部分 stdio 函数以 int 为索引，只接受 0..UCHAR_MAX 或 EOF */
if (isdigit(c))               /* ❌ c 为负（非 ASCII 字节）时是 UB（表越界）*/
if (isdigit((unsigned char) c))   /* ✅ 唯一正确写法 */
```

`getchar()` 返回 `int` 同理：`EOF` 通常是 -1，若用 `char` 接收就无法区分"读到 0xFF"和"读到文件尾"。编码细节（UTF-8 字节序列、BOM、Windows 控制台代码页）在 `05_String_Encoding/` 展开。

## 9. `_Bool`/`bool`、`NULL`、以及"标准版本会改变语义"

```c
#include <stdbool.h>        /* C11/C17：bool/true/false 是宏；C23 起它们是关键字，别重复定义 */
_Bool  b = 5;               /* ✅ _Bool 自 C99 就有，宽度 1 字节，值域只有 0/1 */
int    v = b;               /* 1 —— 任何非 0 转成 1，这是与 int 的本质区别 */
printf("%zu %d\n", sizeof(bool), (int) b);   /* 1 1（<stdbool.h> 里 bool 是 _Bool 的宏）*/
```

`bool` 的正确用法是**语义标签**，不是省内存手段：`sizeof(bool)==1` 但结构体里它仍受对齐影响；位域压缩在 `12_Generic_Container` 讲。

```c
int       *p = NULL;        /* C 里 NULL == ((void*)0)，可隐式转任何对象指针 */
if (p == NULL) { }          /* ✅ 标准写法。别写 if (p == 0)（能过但意图模糊）*/
if (!p) { }                 /* ✅ 惯用，简洁。两种都常见于真实项目 */
```

**变参函数里的 `NULL` 陷阱（LLP64/Win64 上真实存在）**：

```c
execl("/bin/echo", "echo", "hi", 0);        /* ❌ 0 是 int：只压了 4 字节到本该 8 字节的指针槽 */
execl(path, argv0, arg1, (char *) NULL);     /* ✅ 变参终止符必须是指针宽度 */
printf("%s\n", NULL);                        /* ❌ UB。msvcrt/部分实现直接崩，glibc 打 "(null)" 【待实测】 */
printf("%s\n", s ? s : "(null)");            /* ✅ 自己兜 */
```

**`-std=` 会改变语言本身**，这不只是警告列表的问题：

| 选项 | 关键差异 |
|---|---|
| `-std=c99` | 允许 `//`、声明 anywhere、VLA、`long long` |
| `-std=c11` | `_Atomic`、`_Generic`、`_Static_assert`、匿名结构体成员、`quick_exit` |
| `-std=c17` | 修 bug，几乎无新语法 |
| `-std=c23` / GCC 15 默认 `-std=gnu23` | `bool`/`true`/`false`/`nullptr` 成关键字；`int f()` 等价 `int f(void)`；`auto` 可用于类型推导；`static_assert` 免头文件；`#embed` |
| `-std=gnu11` 等 | GNU 扩展全开（`typeof`、语句表达式、柔性数组写法宽松、`M_PI` 可见） |

**所以本仓库强制显式写 `-std=c11`**：否则你按 C11 学，编译器按 C23 编，`int f()` 与 `bool` 的语义都不一样。确认本机默认：

```bat
echo int main(void){return 0;}>_s.c && gcc -dM -E _s.c | findstr __STDC_VERSION__ && del _s.c
:: 201112L = C11 生效；202311L = C23。不写 -std 时的值就是本机默认（待实测）
```

## 10. `const` 与 `volatile`：它们是两个不相干的限定符

```c
const int  n = 10;
int arr[n];                 /* ❌ C 里报错：const 变量不是常量表达式（C++ 里合法！） */
enum { N = 10 };            /* ✅ 编译期常量 */
#define M 10                /* ✅ 预处理替换（见 04_Preprocessor_Macro） */
_Static_assert(N == 10, "N must be 10");   /* ✅ C11 编译期检查，不占运行时 */
```

`const` 的四条真面目：

1. 它是**类型限定符**，不是常量：`const` 变量仍有地址、仍在 `.rodata` 或栈上。
2. 通过它初始化后**再改就是 UB**：`int *q = (int *)&n; *q = 1;` —— 编译器可能直接把 `n` 折成立即数，你改的内存和读的值不一致，静默分叉。
3. 它是**接口契约**：`void f(const char *s)` 承诺不修改，调用方因此可以传字面量。
4. 它**可被绕过而不产生诊断**（`void *` 一转就没约束了），所以 `const` 是自律工具而非安全边界。

`volatile` 常被误解，只保证三件事：**每次访问都真的发生（不缓存进寄存器）、不被删除、不被合并**；相邻 volatile 访问之间的顺序是实现定义，**它不提供原子性，也不提供线程间可见性保证**。

```c
volatile int g_stop;         /* ✅ 用途一：信号处理函数里置位，主循环轮询（配合 sig_atomic_t 更标准）*/
volatile struct Reg *r = (void *)0x40001000;   /* ✅ 用途二：内存映射寄存器（裸机/驱动）*/
/* ❌ 错误用途：两个线程共享的计数器写 volatile 就当原子 —— 不是。见 17_Concurrency */
```

`const volatile` 是合法组合：只读又每次必须重新读（硬件状态寄存器）。

## 11. 枚举：C 里它是"带类型的 int"，不是封闭集合

```c
enum Color { RED, GREEN, BLUE = 5, YELLOW };   /* 0,1,5,6 —— 显式值之后自动 +1 */
enum Color c = GREEN;
c = 42;                        /* ✅ C 合法：枚举变量的值是"实现定义的整型"，可存非枚举值 */
                              /* ❌ C++ 不允许（C++ 里 enum class 才封闭）——移植时会炸 */
enum Color *pc;                /* 别拿枚举做指针算术，没有意义 */
```

三个实用点：

```c
/* 1) 穷尽性检查：switch 漏一个值就让编译器喊出来 */
switch (c) { case RED: /* ... */ break; case GREEN: /* ... */ break; }
/* 打开 -Wswitch-enum（不在 -Wall 里）：连 default: 也照样警告缺失分支 ——
   加新枚举值时能一次性找到所有需要跟着改的地方。没有 default 的 switch
   漏 case 时 -Wall 就会警告，这是最省心的写法：故意不写 default。 */

/* 2) 位标志：用显式 1<<n，避免"用 enum 相加"的歧义 */
enum { F_RDONLY = 1u << 0, F_WRONLY = 1u << 1, F_APPEND = 1u << 2 };
typedef unsigned OpenFlags;                 /* 位标志存进 unsigned，而不是 enum */

/* 3) 跨 ABI 的定宽枚举：C 的 enum 底层类型是实现定义的（可能是 int/unsigned/size_t），
      存进文件或过网络时必须用固定宽度类型 + 手工校验范围。
      GCC 的 __attribute__((packed)) enum 是扩展，-Wpedantic 会警告（内核 uapi 头为此套 __extension__）【待实测】 */
```

`enum` 的经典用途：**给函数返回错误码**，见 `12_Generic_Container`（错误处理是它的正式主题）。

## 12. 严格别名：`-O2` 下最反直觉的 UB

规则（C11 6.5p7 大意）：**访问一个对象时，用于访问的指针类型必须与对象的实际类型"兼容"，或是字符类型（`char`/`signed char`/`unsigned char`），或是该类型的（限定）版本。** 违反 = UB，且 GCC 在 `-O2`（默认开启 `-fstrict-aliasing`）会**据此重排读写**。

```c
float f = 1.5f;
int bits = *(int *) &f;        /* ❌ 违反严格别名：f 的实际类型是 float，用 int 左值访问 */
                               /* -O0 下常常"正确"，-O2 下可能读到旧值或被优化掉 */
```

合法/推荐的三种破法：

```c
/* 1) memcpy —— 首选。零开销，编译器优化成一条 movd/mov 指令 */
int bits; memcpy(&bits, &f, sizeof bits);

/* 2) 字符类型遍历 —— 标准明确放行（见 01 第 8 节） */
unsigned char *pb = (unsigned char *) &f;

/* 3) union 双成员 —— C 里"写入一个成员再读另一个"是实现定义行为，
      GCC/Clang 都明文保证按位重新解释（这是 C 与 C++ 的真实差别） */
union { float f; int32_t i; } u = { .f = 1.5f };
int32_t bits = u.i;            /* GCC/Clang 保证可行；MSVC 不保证 */
```

编译器还会检查明显违规：`-Wstrict-aliasing`（GCC 需配合 `-O2`，`=1/=2/=3` 逐级更啰嗦）。

自救与自残：

```bat
gcc -std=c11 -Wstrict-aliasing=2 -O2 x.c      :: 让编译器告诉你哪里危险
gcc -std=c11 -fno-strict-aliasing x.c         :: 关掉假设 —— 全量重写网络协议栈时的粗暴做法
                                              :: 代价：优化器不能假设两个不同类型指针不指向同一内存
                                              :: 于是循环里每次都要重新 load，性能明显下降。
                                              :: Linux 内核整个用 -fno-strict-aliasing 编（历史+安全），
                                              :: 但那是"全项目一致"的决定，不是单个文件的借口。
```

`__attribute__((may_alias))`（GCC）可以给某个类型重新打"我允许别名"的标签，`<immintrin.h>` 的向量类型就是这么定义的（`__m128` 等）——写 SIMD 代码时会碰到。

## 13. UB 清单（按你会碰到的顺序）+ 编译器怎么"利用"它

| 类别 | 具体条目 |
|---|---|
| 内存 | 越界读写、悬垂指针解引用、未初始化读、`free` 非堆/二次 `free`、未对齐访问、`sizeof` 数组参数、返回局部地址 |
| 算术 | 有符号溢出、`/0`、`%0`、`INT_MIN / -1`、`-INT_MIN`、移位量 ≥ 类型宽度、左移负数、`abs(INT_MIN)` |
| 求值顺序 | `i = i++`、`f(i, i++)`、`a[i] = i++`（同一标量在序列点两次修改） |
| 类型 | 严格别名违规、类型双关 `*(int*)&f`、以不匹配类型调用函数指针、写入 `const` 对象、写字面量 |
| 库调用 | `printf` 格式与实参不符、`%s` 传非终止数组、`<ctype.h>` 传负 `char`、缓冲区长度不足、`NULL` 当字符串、变参里 `0` 当指针哨兵 |
| 并发 | 两个线程无同步访问同一对象（**C11 明确定义为 data race = UB**，不是"大概会读到旧值"，见 `17_Concurrency`） |
| 其它 | 违反 `restrict` 承诺、`setjmp` 后使用非 volatile 局部量、`main` 之外递归到爆栈 |

### 13.1 为什么 UB 不等于崩溃：三个"编译器反过来利用它"的实例

**实例 A：空指针检查被删。** 解引用本身就意味着"我保证这里非空"，优化器据此删掉后续判空。

```c
int f(int *p)
{
    *p = 1;                       /* ← 从这条推出 p != NULL（否则程序无意义）*/
    if (p == NULL) return -1;     /* ← 于是这个分支被当死代码删除 */
    return *p;
}
```

2014 年 Linux 内核 `tty_lock()` 就因为这个把安全 panic 优化没了（CVE 级别）。验证方法：

```bat
gcc -std=c11 -O2 -S f.c -o - | findstr /i "NULL"
```

**实例 B：溢出检查被删。** `if (x + 1 < x)` 在有符号类型上被假设永假（溢出=UB），整段消失。

**实例 C：循环边界被改写。**

```c
void z(int *a, int n) { for (int i = 0; i < n; ++i) a[i] = 0; }
/* 优化器知道 i 不会"绕回"（有符号溢出 UB），可以放心把循环转成 do-while 或
   分块向量化；当 n 是负数时，原代码"什么都不做"，新版本"做很多次"。 */
```

同一个道理：**你依赖 UB 得到的一切"实测结果"，都是编译器的临时许可**，不是事实。想验证自己的判断，就用 `-fsanitize=undefined`（UBSan，报具体行）而不是靠肉眼和 `-O0`。

### 13.2 必需诊断 vs 沉默

C 只要求编译器对**极少数**情况给诊断（语法错误、约束违反如 `const` 赋值不等）。越界、UB、`printf` 格式串与实参数量不符（部分情况给警告）等等**标准不要求报告**。所以"编译没报错"的信息量约等于零。

## 14. 警告开关：分层用，而不是一次全开

```bat
:: 第 0 层：永远开（本仓库所有 build.cmd / Makefile 都用这组）
gcc -std=c11 -Wall -Wextra -Wpedantic -g x.c

:: 第 1 层：新项目 / 重构期，强烈建议
gcc -std=c11 -Wall -Wextra -Wpedantic \
    -Wshadow -Wconversion -Wsign-conversion -Wswitch-enum -Wundef \
    -Wwrite-strings -Wcast-qual -Wstrict-prototypes -Wmissing-prototypes \
    -Wold-style-definition -Wdouble-promotion -Wformat=2 -Wvla -g x.c

:: 第 2 层：CI 里把自己的代码变成错误（别对第三方头用）
gcc -std=c11 -Wall -Wextra -Werror x.c -o x
::   只对特定警告升级： -Werror=implicit-function-declaration -Werror=return-type
::   第三方头降噪： -isystem 3rdparty/include   （而不是 -I）
```

几个选择理由：

- `-Wshadow`：局部变量遮蔽外层同名变量/参数——**在多层循环和重构里最常见、最难自查**的一类错。
- `-Wconversion -Wsign-conversion`：把第 3、4 节的隐式转换全部暴露。**代价是极吵**（连 `char c = arr[i];` 都警告），所以只对"新写的代码"开，别对存量项目开，否则会被淹没到全部忽略。
- `-Wformat=2`：格式串检查加上"非字面量格式串"警告，`printf(user_input)` 这种直接判死刑（安全审计必查项）。
- `-Wnull-dereference`：需要 `-O2`（依赖优化器的可达性分析）才有效。
- `-Wvla`：把变长数组用法报出来，防止你不知不觉写出不可移植代码。
- 单个警告最小化关闭（而不是整文件关）：

```c
#pragma GCC diagnostic push
#pragma GCC diagnostic ignored "-Wunused-parameter"
void callback(int code, void *ctx) { /* 故意不用 ctx */ (void) ctx; }
#pragma GCC diagnostic pop
```

**GCC 15 的默认变化值得单独记住**：`implicit-function-declaration`、`implicit-int`、不兼容指针类型在新版 GCC 里已从警告升级为**错误**（C23 方向）。这意味着从老项目搬来的"能编"代码在 GCC 15 上会直接编译失败——这是好事：它拦住的正是第 5 节里那种静默变垃圾的场景。【待实测：拿一个不写原型就调用的文件试试】
